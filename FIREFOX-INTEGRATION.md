# Nexora Firefox integration

This build adds Firefox/Guardian as an independent connection module. The existing Parham V2Ray/Xray engine files are intentionally not replaced or rewritten.

## Supported targets

| Target | Firefox login / locations / ping | Firefox full-device VPN |
|---|---:|---:|
| Android | Yes | Yes (separate `VpnService` + Go core + HEV TUN) |
| Windows | Yes | Yes (separate Go core + installed TUN service) |
| Linux | Yes | System proxy mode (no full-device TUN) |
| macOS | Yes | System proxy mode (no full-device TUN) |

iOS is not part of this build. Linux and macOS use the core's system-proxy mode (GNOME/KDE on Linux, `networksetup` on macOS) and the V2Ray engine uses the bundled `xray` binary the same way.

## Build

Use the existing `.github/workflows/build.yml` workflow. Android builds the Nexora Go mobile AAR and native HEV adapter before Flutter builds. Windows builds the Nexora Go core and TUN service, then places both executables in `firefox-core/` beside the app executable. Existing Xray packaging remains in place.

## Isolation from the existing engine

The imported Dart API/models and UI live under `client/lib/firefox/`. Vendored core/HEV sources live under `client/third_party/nexora-core/`. Android integration is generated by `tools/prepare_firefox_android.py` after `flutter create`; its service uses a separate method channel (`parham/firefox`). The existing files `vpn_service.dart`, `vpn_android.dart`, `vpn_android_stub.dart`, `xray_config.dart`, `dns_tunnel.dart`, and `connect_fx.dart` are unchanged. The app-level connection buttons only coordinate so that two full-device VPN tunnels are not started at once.

## Mozilla sign-in

The embedded WebView opens the official `accounts.firefox.com` sign-in page. Parham forwards the short-lived Firefox WebChannel session token to the local Nexora core; it does not read or store the account password. Any email or authenticator verification requested by Mozilla remains in that official page.

## Options page (all platforms; system proxy only Linux/macOS)

`client/lib/firefox/firefox_options_page.dart` (app bar icon on the Firefox page) edits the core's config.json in place:

| Option | Config key | Notes |
|---|---|---|
| Connection mode (Linux/macOS) | `system_proxy.mode` (`set` / `clear`) | system proxy or proxy-only; stored in app prefs `ff_desktop_mode` |
| Personal Cloudflare relay | `network.api_relay`, `network.api_relay_enabled` | Worker code: `client/assets/relay/nexora-relay-worker.js` (copy button in the app) |
| Shared relay | `network.shared_relay_enabled` | |
| ECH | `network.api_relay_ech` | on / require / off |
| ClientHello split | `network.hello_split` | off / first-byte / sni / record |
| Upstream SOCKS5 | `network.upstream_proxy(_enabled)` | e.g. local v2ray 127.0.0.1:10808 |
| DNS | `dns.servers`, `dns.fallback_to_system` | auto, Cloudflare DoH/DoT, Google, Quad9, system |
| Backup | `/api/backup` | saved to ~/Downloads; restore by path |

### Cloudflare relay: what to replace
Address format: `https://WORKER.ACCOUNT.workers.dev/?secret=SECRET`
- Paste the copied Worker code over Cloudflare's default code, Deploy.
- Worker → Settings → Variables and Secrets → Secret `RELAY_SECRET`.
- `WORKER.ACCOUNT` = the address Cloudflare shows after Deploy; `SECRET` = the same RELAY_SECRET value.
- Optional variable `ALLOW` (e.g. `firefox.com,mozilla.com,mozilla.org`) locks the relay to those hosts.
